# Character Motive Engineering

## Use when

The character has traits but no generator. Build a stable rule that can produce several surface labels under different objects and pressures.

## Do not use when

Do not confuse consistency with monotony. Motives can conflict, learn, decay, or acquire exceptions. The requirement is causal legibility, not static personality.

## Core model

```text
stable motive + object/context -> behavior -> reader label
```

**The label is an observation, not a character parameter.**

A strong new scene may break the reader's model. It should not break the character's generator without cause.

## Workflow

1. Delete trait adjectives from the character sheet.
2. Write one or two durable priorities: debt, possession, fairness, status, curiosity, control, kinship, craft, survival, recognition.
3. Define the priority's **domain**. To whom or what does it apply? Where does it stop?
4. Place the same priority in unlike contexts.
5. Let readers infer an easy label from the first two outputs.
6. Introduce a case that violates the label but still follows the priority.
7. Repeat until the reader can predict the person without reducing them to one adjective.

## Hard rules

- “Cruel but loves kittens” is not depth by itself.
- Do not use tenderness as automatic moral redemption.
- Do not make every contradiction secretly noble.
- Competence is local. A character can be brilliant about one recurring object and naive elsewhere.
- A character need not understand their own generator in theoretical language.

## Minimal pair

Flat contrast:

> He is stingy, but once a year he gives a large anonymous donation.

Generated contrast:

> He refuses to split bills by “roughly half,” yet spends freely to repay any debt he can name exactly.

The second pair can arise from one rule: **accounts must close cleanly**. “Stingy” and “generous” are reader labels that fail on different transactions.

## Counterexamples

- A genuinely impulsive character may lack one stable decision rule; instability itself can be causal if the triggers are legible.
- A sudden value change can be correct after a specific event that changes what the character believes, fears, or owes.

## Return shape

Return **generator -> domain -> three predicted behaviors -> likely reader labels -> scene that breaks each label**. Keep the generator shorter than the behavior list.
